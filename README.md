# 涉老取款紧急干预

在“立即放款”与“主观拒绝”之间，提供第三选项：**有时限、可申诉的紧急核实与保护措施**。

核心立场：年龄、金额、陪同者身份、家属反对**只能触发核实，不能自动否定**客户的交易能力；任何保护措施必须有**具体事实理由、明确期限、责任人和客户告知**，届满按**最新有效决定**执行，无有效决定即放行；未经确认的主观标签不外溢到其他业务；警方完整证据与资金去向仅在合法授权（L2 受案/L3 文书）后披露。

## 资料与代码

- `docs/service-design.md`：服务设计全文（原则、角色、状态机、触发规则、时限表、保护措施、申诉、柜员界面、客户告知、幂等接入、外溢隔离、警方披露门 L0–L3、防误伤与审计）。
- `contracts/domain.schema.json`：事件信封契约。沿用 4 个聚合（withdrawal_case / observed_signal / protective_hold / final_decision），原始 5 类事件语义不变，扩展至完整案件所需的 20 类事件及 payload 约束。
- `src/validator.py`：事件信封与 payload 的中文错误校验（纯标准库）。
- `src/case_kernel.py`：幂等案件内核——
  - `EventStore`：event_id + 同版本 + 自然键三重幂等去重，版本冲突隔离，**永久保留原 `occurred_at`**；
  - `CaseProjector`：从只追加事件流推导案件状态与持有措施链；
  - `Sweeper`：届满扫描，机械执行“无有效决定默认放行”“申诉 2h 未决自动解除”“按最新有效放行决定执行”，可重复扫描；
  - `CaseCommands`：业务规则入口——印象/家属反对/单纯未接通不能单独支撑暂停，止付必须有客户凭证或法律文书，48h 警方窗口须 L2/L3，购房加速时限减半；
  - `TellerView` / `CustomerNotice` / `ExternalBusinessView` / `PoliceDisclosureGate`：柜员倒计时视图、客户书面理由与申诉入口、跨业务外溢隔离、警方分级披露门。
- `data/sample.json`：单条开案样例；`data/sample_case.json`：一个完整案件事件序列（陪同者代答催促→三要素暂停→家属反对仅触发再核实→客户单独表达购房意愿→主管复核放行）。
- `tests/`：契约与内核测试，覆盖幂等/冲突/乱序、触发不等于否定、届满放行、最新有效决定、申诉超时、止付合法性、标签隔离与授权门。

## 关键时限（默认配置，详见设计文档 §8）

| 阶段 | 时限 | 到点默认 |
|---|---|---|
| 现场初始核实 | T0+15 分钟 | 通过即放款 |
| 初始保护暂停 + 主管复核 | T0+45 分钟 | 无有效决定默认放行 |
| 延续核实段 | 单次最长 4 小时 | 无有效延续批准即放行 |
| 警方响应窗口（须 L2 受案） | 最长 48 小时 | 无法律依据/决定即放行 |
| 快速申诉独立审查 | 2 小时（现场力争 30 分钟换人） | 超时自动解除措施 |
| 真实购房加速 | 前三段时限减半，主管待办置顶 | — |

## 事件接入约定

1. `event_id` 全局唯一，来源系统重试必须沿用原 ID；
2. 换 ID 的重发靠自然键（聚合 + 类型 + 发生时间 + 内容）去重；
3. `occurred_at` 保留事实真实发生时间，时间轴不按接收顺序重写；同聚合同版本内容冲突进异常队列；
4. 事件只追加：撤销/延续/覆盖由 `HOLD_REVOKED` / `HOLD_EXTENDED` / `DECISION_SUPERSEDED` 等新事件表达，不删除历史。
