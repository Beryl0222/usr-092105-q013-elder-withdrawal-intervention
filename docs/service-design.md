# 涉老取款紧急干预服务设计

版本 0.1（2026-10-05）

## 1. 服务定位

在高风险取款现场，柜员以往只有两个动作：**立即放款**或**主观拒绝**。本服务在二者之间提供第三选项——**有时限、可申诉的紧急核实与保护措施**：

- 对客户：不经定罪式盘问即可获得短暂时限完成自主表达、单独沟通与必要联系；
- 对柜员：不再以个人主观判断直接否定客户的交易能力，而是按流程收集信号、尝试联系、提交主管复核，并对记录真实性负责；
- 对真实购房等正当大额交易：保护措施有明确理由、期限和升级责任，**期限届满按最新有效决定执行，无有效决定即放行**，不无限冻结。

核心命题：年龄、金额、家属反对只是**核实触发器**，不是**能力否定器**。

## 2. 非目标

- 不做定罪推断：服务记录可观察事实与各方决定，不输出“某人是诈骗分子”的结论；
- 不对陪同者/家属做任何业务限制——他们不是本案当事人；
- 邀请联系是流程动作，不是对客户心智状态的医学判断；
- 不替代法律手续：止付需客户请求或法律规定情形，完整证据与资金去向披露给警方需合法授权。

## 3. 设计原则

1. **能力推定（Presumption of capacity）**：成年客户被推定为有交易能力。年龄、金额、陪同者身份、家属反对**只能触发核实，不能自动否定**。是否理解并承担交易后果，只能在单独沟通、必要核实后评估，且结论只能是“建议再核实/建议谨慎”；“无行为能力”只能由法律程序认定。
2. **最小限制与最短必要时限**：保护措施是流程性暂停而非处罚，适用最短必要时限；真实购房等赶节点的情形适用加速条款（§8）。
3. **理由 + 期限 + 责任人三要素**：任何限制资金可用性的安排，必须同时给出具体事实理由（不是“看起来像诈骗”）、明确截止时间、对当前状态和升级结果负责的人。
4. **时间轴不动**：事实的真实发生时间（`occurred_at`）以来源系统为准并永久保留；重复通知靠 `event_id` / 自然键去重，不以接收顺序重写历史。
5. **最新有效决定优先**：期限届满时，按截至届满时刻**最新一份合法且有效的复核决定**执行；没有有效决定则走默认动作（放行）。
6. **每个延迟都有主人**：每段时限都有责任人；到点未决不是系统卡顿，而是责任人的考核事件。
7. **申诉即权利**：现场即可快速申诉，入口与书面理由同时交付；申诉审查期间保护措施不自动延长，申诉超时未决则措施自动解除。
8. **标签不外溢**：未经客户确认或未在本案中完成证据化的主观观察标签，**不得写入客户主档，不进入其他业务、授信、营销或风控通用名单**。
9. **披露需授权**：完整证据与资金去向仅在收到合法授权（受案回执/协查/冻结法律文书）后向警方提供；此前只有有限联系点。

## 4. 关键术语

| 术语 | 含义 |
|---|---|
| 案件（case） | 一次高风险取款触发的全流程记录，1 笔取款申请 = 1 个案件 |
| 陪同者（companion） | 现场代答、催促或阻止客户接电话的人；记录其行为，不对其做业务限制 |
| 可观察信号（observed signal） | 柜员/设备当场可见、可复现的事实，含置信度标记（事实 / 印象 / 系统提示） |
| 保护措施（protective hold） | 对该笔交易的暂停安排，含理由、期限、批准人、升级职责 |
| 最终决定（final decision） | 放行或止付，须有客户请求或合法依据、决定人、客户已获书面理由 |
| 快速申诉（expedited appeal） | 客户当场或收悉后 48 小时内提出，优先审查、书面答复 |
| 原始时间戳 | 事实在网点/支付系统中真正发生的时间，必须保留 |
| 最新有效决定 | 截至某时刻，序列中最后一份权限内、依据完整、未被撤销的复核决定 |

## 5. 角色与权责

| 角色 | 权利 | 责任/禁忌 |
|---|---|---|
| 客户（老年取款人） | 单独沟通、自主表达；阅读/听读书面理由；当场快速申诉；要求加速；随时撤回配合 | 不因年龄/金额被直接拒绝；不被当病人盘问 |
| 柜员 | 触发案件、记录信号、尝试联系、提请复核 | 不得自行决定止付或长期暂停；不得让陪同者代答；不得把主观印象当事实 |
| 主管（网点负责人） | 初始暂停批准、45 分钟复核、4 小时段延续、48h 段批准、加速审批 | 必须给书面理由；到期必须作出去留决定；对“无决定默认放行”的结果负管理责任 |
| 后备主管/支行长 | 主管不可达时自动升级的接收人 | 时限不变，不因其接手而重新起算 |
| 独立复核人 | 审查申诉（非原经办人，建议上级行值班岗/合规岗） | 只依据案件记录与客户当下意愿独立判断 |
| 支付系统 | 执行暂停/放行/止付指令；幂等重发状态通知 | 只执行带三要素且未过期的指令；指令缺失或过期则默认放行该笔 |
| 柜员界面 | 显示倒计时、责任人、下一动作；交付书面理由与申诉入口 | 不把未经确认的主观标签呈现为事实；不允许跳步 |
| 警方 | L0–L1 提供电话判断；L2 受案后请求有限材料；L3 凭文书调取完整证据与资金去向 | 无授权时系统拒绝导出证据包/流水（§15.4） |
| 其他业务系统 | 仅经“外溢视图”看到客户确认或已受案/已定性的状态码 | 看不到信号明细、印象记录、陪同者与申诉内容 |

## 6. 案件生命周期与状态机

```
IDLE
  │ 核实触发器成立（§7），柜员登记开案
  ▼
OPENED
  │ 业务确有必要延缓时（默认路径是当场核实后放款，不暂停）
  ▼
IN_VERIFICATION ── 客户放弃/撤回交易 ─────────────► CLOSED_RELEASED
  │  （单独沟通 + 信号采集 + 首轮联系，T0+15min 内）
  │
  ├─ 客户自主表达一致、无成立的新风险 ───────────► CLOSED_RELEASED
  ├─ 客户/他人提出快速申诉 ──────────────────────► PENDING_APPEAL
  ├─ 有具体事实理由需要更多时间，主管批准三要素 ──► HELD
  │
  ▼
HELD（保护措施生效，界面显示截止倒计时与责任人）
  ├─ 期限届满且无有效决定 ───────────────────────► CLOSED_RELEASED（HOLD_EXPIRED → FUNDS_RELEASED）
  ├─ 主管复核决定放行 / 申诉成立撤销暂停 ─────────► CLOSED_RELEASED
  ├─ 主管复核决定延续（新三要素、新记录）─────────► HELD
  ├─ 客户书面/录音请求止付，或警方 L3 文书到达 ──► STOP_PAYMENT
  └─ 申诉提出后等待独立复核（措施不因此延长）────► PENDING_APPEAL
        ├─ 撤销暂停 ───────────────────────────► CLOSED_RELEASED
  │  ├─ 维持（须给新的书面理由）──────────────► HELD
  └─ 2h 未决 ───────────────────────────────► CLOSED_RELEASED（超时解除）

STOP_PAYMENT：转正式止付/冻结法律流程，退出本服务计时，后续按法律文书管理。
```

要点：

- 除 HELD 外任何状态都不延迟放款；进入 HELD 必须满足 §9.1 要件；
- “无有效决定默认放行”在每个时限点机械执行，不依赖经办人良心；
- 事件只追加：撤销、延续、覆盖分别由新事件表达（§15.2），历史记录不删除。

## 7. 触发规则：核实而非否定

### 7.1 核实触发器（任一成立即应开启案件，但不改变客户默认权利）

**A. 现场可观察信号**

1. 陪同者替客户回答核心问题（“取多少/做什么用/给谁”），或客户开口前看陪同者脸色；
2. 陪同者持续催促（“快点、我赶时间”）、阻止客户接电话或阻止客户单独与工作人员交谈；
3. 客户对资金用途表述前后矛盾，或复述时依赖陪同者提示；
4. 客户明显紧张、反复向门外/手机确认——**仅作“印象”记录，单独不足以触发暂停**；
5. 适老服务卡、近期挂失、近期授信或账户异动与本笔交易相关联（系统信号，可自动开案）。

**B. 交易上下文（系统）**

1. 金额达到本行大额现金/转账门槛（阈值由分行按当地房价等设定，服务不写死金额）；
2. 资金去向为陌生对手方、新开账户、境外账户、虚拟资产/赌球类商户码、多账户归集；
3. 与账户习惯显著偏离（长期稳定现金偏好账户突然全额转走）；
4. 客户称“购房”但暂无可快速核验的上下文（无中介名称、无合同编号、收款方为个人账户且坚持现金）——仅触发**优先核实**，不自动暂停。

**C. 联系与外部信号**

1. 客户预留电话无人接听、关机，或被现场人员阻止拨打；
2. 预留紧急联系人反馈异常，或**家属反对**——家属反对**仅触发再核实**，不能作为否定客户意愿的依据；
3. 96110/反诈中心或警方热线存在针对该客户或本笔交易的预警。

### 7.2 明确不是否定理由

下列各项**不得**作为暂停、止付或拒绝服务的唯一依据：客户年龄；认知障碍诊断（无生效行为能力法律文书时仍以当场单独沟通为准）；金额大（含真实购房）；家属/子女反对；客户拒绝回答某些问题；客户接受他人“指导”但暂无证据证明该指导违法。

### 7.3 信号分级与记录纪律

| 级别 | 说明 | 能否支撑暂停 |
|---|---|---|
| fact（事实） | 可复现，如“陪同者三次打断客户回答用途并说‘别跟他们说’” | 可开案；多条成立可支撑初始暂停 |
| impression（印象） | 工作人员主观感觉，如“感觉客户被控制” | 必须打 impression 标记；**不得单独支撑限制**，不外溢 |
| system_notice（系统提示） | 支付/风控系统自动提示，含来源与版本 | 可开案；能否暂停取决于提示等级与沟通结果 |

每条信号记录：观察者、真实发生时间、情境、客户/陪同者原话或行为、级别。**严禁对陪同者作身份定性（“骗子”），严禁对客户作医学定性。**

## 8. 时限与里程碑

默认配置；分行可在合规范围内调参，调参必须留痕。T0 = 开案时间。

| # | 阶段 | 时限 | 责任人 | 到点默认动作 |
|---|---|---|---|---|
| 1 | 现场初始核实（单独沟通、信号采集、首轮联系） | T0+15 分钟 | 柜员（大堂经理辅助） | 核实通过→放行；有具体理由→提请初始暂停 |
| 2 | 初始保护暂停（含主管第一次复核） | T0+45 分钟 | 主管 | **无有效决定默认放行**（界面红色警示） |
| 3 | 接触失败/等待紧急联系人回电等延续段 | 单次最长 4 小时 | 主管 + 反诈联络人 | 无有效延续批准→放行；警方已受案走 #4 |
| 4 | 警方响应窗口（须主管凭具体事实批准 **且** 警方已受案/有预警记录） | 最长 48 小时 | 反诈联络人 + 主管 | 无合法延续依据→放行；L3 文书到达→转正式流程 |
| 5 | 快速申诉独立审查 | 2 小时（现场申诉力争 30 分钟内换人完成） | 非原经办人（独立复核人） | 超时未决→措施自动解除并放行，申诉留痕继续 |
| 6 | 是否进入正式止付的最终复核 | T0+48 小时 | 支行长或授权审批人 | 无客户请求、无法律依据、无有效决定→**放行** |

补充规则：

- **真实购房加速条款**：客户提供合理交易上下文（合同编号、中介、收款方与楼盘/监管账户一致等，仅形式审查）且对资金安排自主表述清楚的，#1–#3 时限压缩一半，并自动排到主管待办首位；
- 客服/线上渠道触发的案件以回拨、弹窗单独确认等方式接触，时限可更短，但同样适用“无有效决定默认放行”；
- 时限不因换经办人、升级后备主管而重新起算。

## 9. 保护措施（protective hold）

### 9.1 成立要件（三要素 + 告知）

每条暂停记录必须包含：

1. **具体事实理由**：引用信号 ID 与联系结果（如“信号 #3、#5 成立 + 96110 预警命中”），不得仅写“疑似诈骗”；
2. **期限**：截止时间戳，引用 §8 的某一段；
3. **批准人与升级责任**：工号、角色，到点前由谁决定、未决定的后果（默认放行）；
4. **客户知悉**：书面理由的交付时间；
5. **性质声明**：这是流程性暂停，不是对客户的不利评价，不是扣款或没收。

### 9.2 届满处理

- 按 §8 默认动作执行：除有客户止付请求或法律依据外，**届满即放行**；
- 期限内出现最新有效决定（申诉成立、主管复核、警方文书）时，按 §10 执行；
- 延续必须是一条**新的 hold 记录**（新理由或同一理由 + 警方记录 + 新期限 + 新批准人），不得静默改期，形成可审计链条。

### 9.3 禁止事项

- 禁止“先冻再想”：缺 §9.1 要件的暂停指令，支付系统拒绝执行；
- 禁止用换柜员、换案件号变相延长；
- 禁止对陪同者账户做任何联动限制；
- 禁止以 impression 信号作为唯一依据。

## 10. 联系尝试与“最新有效决定”

### 10.1 联系尝试记录

每次尝试记录：对象（客户本人单独再确认 / 预留紧急联系人 / 96110 / 警方）、方式（当面单独、电话、回拨）、开始与结果时间、结果分类（接通确认意愿 / 接通但意见不同 / 未接通 / 被阻止 / 预警命中）、记录人。**客户被阻止接电话本身构成一条 fact 信号。**

### 10.2 决定有效性判定

一份复核决定有效，当且仅当：

1. 由 §5 中具备该阶段权限的角色作出；
2. 依据可溯源（引用具体信号、联系结果或预警记录）；
3. 作出时仍在 §8 时限内；
4. 未被更新的决定撤销；
5. 止付/长冻结类决定附有客户书面或录音请求，或明确法律依据标识（文书编号）。

### 10.3 执行规则

```
在每个截止时刻：
  D = 截至此刻最新一份有效决定
  若 D 存在：执行 D（放行 / 延续暂停（附新三要素）/ 转正式流程）
  否则：    执行该阶段默认动作（放行）
```

## 11. 申诉机制

| 项目 | 安排 |
|---|---|
| 谁可申诉 | 客户本人（任何时候，含暂停中、放行后）；客户明确授权的人可代为表达，但权利属于客户 |
| 何时 | 现场可立即提出；收悉书面理由后 48 小时内为快速申诉窗口（与措施期限相互独立，不导致措施延长） |
| 如何提出 | 告知书/短信中的**申诉码**扫码、专线电话、现场要求换人，三通道等效 |
| 谁审查 | **非原经办人**：现场 30 分钟通道由另一名主管或上级行值班岗独立复核；合规岗抽查 |
| 审查内容 | 触发是否合规、信号是否属实、三要素是否齐全、客户当前自主意愿、是否存在可形式核验的正当交易上下文 |
| 结果 | 撤销→立即放行；维持→给新的书面理由与后续权利；2 小时未决→措施自动解除 |
| 再申诉 | 5 个工作日内可向上级行投诉，全量留痕；胜诉或撤销的案件 24 小时内清除一切外溢标记 |
| 误伤救济 | 因流程延误影响真实交易的，走加急放行、出具情况说明等紧急协助；流程瑕疵列入主管考核 |

## 12. 陪同者处理纪律

- 开案后 3 分钟内提供**与客户单独交谈的机会**（“我们按规定需要和您本人单独核对一下交易信息”），不评价陪同者；
- 记录陪同者对单独交谈的反应（拒绝让客户离开、贴窗旁听、替客户收执告知书等，均按 fact 记录）；
- 不向陪同者解释案件细节、不要求陪同者签字、不把告知书交给陪同者；
- 陪同者强行带客户离开：记录但不限制人身自由，按 §8 #3 接触失败处理；已命中预警的，可在合法授权范围内向警方提供有限信息。

### 13.2 录入面板

- 客户原话：可写可录（录音需客户知情）；
- 陪同者行为快捷标签：替答 / 催促 / 阻止接电话 / 阻止单独交谈 / 其他；
- 交易上下文：用途、收款方、有无合同/中介/楼盘名称。

### 13.3 联系面板

“客户本人手机独立接听 / 预留紧急联系人 / 96110 / 警方联络人”，每个按钮自动生成 CONTACT_ATTEMPTED 记录，未接通须选原因。

### 13.4 动作表单

- 暂停：勾选理由（引用信号）→ 选时限段 → 自动生成截止时间 → 主管批准；三要素缺一，提交禁用；
- 放行：记录客户自主表达摘要即可；**任何角色都不得在无合法依据时锁定该按钮**；
- 止付：强制附客户请求凭证或法律文书编号，否则不能提交。

### 13.5 客户告知预览

提交暂停同时生成大字号《交易核实安排告知书》：案件号、“这不是拒绝、不是冻结您的钱”、平实语言理由、最晚处理时间、主管姓名工号、申诉码与专线电话、警方如已介入的如实说明。

## 14. 客户同步交付

| 时点 | 交付 |
|---|---|
| 开案时 | 口头说明 + 一页纸《为什么需要核实》（大字号、口语化）+ 短信链接（可由客户自行转发给信任的人） |
| 暂停生效时 | 《交易核实安排告知书》纸质件：三要素 + 申诉码 + 专线电话 |
| 每次状态变化 | 短信/小程序通知：当前状态、最晚结果时间、现在能做什么（含专线电话） |
| 放行时 | 立即到账/交付提示，并注明“本次核实不影响您在本行的任何服务” |
| 止付/转正式流程时 | 书面说明法律依据、后续手续、申诉与救济途径 |
| 申诉答复时 | 书面（含电子）答复，说明理由与进一步权利 |

## 15. 幂等接入与数据治理

### 15.1 接入规则

1. `event_id` 全局唯一；来源系统重试必须沿用原 ID（与 README 既有约定一致）；
2. 自然键（`aggregate_id + 事件类型 + 业务序号 + occurred_at`）内容一致的重复通知：丢弃但计入“重复投递”指标；
3. **保留原 `occurred_at`**：支付系统 12:00 发生、12:09 重推的事件，案件时间轴仍写 12:00；视图按发生时间排序，不按接收时间；
4. 同聚合同 `version` 内容冲突 → 进异常队列，不改写既有记录；
5. 事件只追加（append-only）：撤销/变更以新事件表达。

### 15.2 聚合与事件总表

沿用契约已有 4 个聚合；在原 5 类事件语义不变的前提下扩展：

**withdrawal_case**

- `TRANSACTION_FLAGGED`（原有，开案）
- `CONTACT_ATTEMPTED`（原有，联系尝试）
- `CASE_STATUS_CHANGED`（状态迁移，系统推导，含原因）
- `CUSTOMER_STATEMENT`（客户单独表达的意愿与原话摘要）
- `COMPANION_BEHAVIOR`（陪同者可观察行为）
- `ACCELERATION_REQUESTED` / `ACCELERATION_GRANTED`（购房等加速）

**observed_signal**

- `SIGNAL_RECORDED`（新增信号，级别 fact / impression / system_notice）
- `SIGNAL_WITHDRAWN`（信号经核实不属实而撤回——标记不删除）

**protective_hold**

- `HOLD_APPLIED`（原有，payload 含理由、截止、批准人、客户知悉时间）
- `HOLD_REVOKED`（撤销来源：申诉成立 / 主管复核 / 警方反馈排除）
- `HOLD_EXPIRED`（届满无有效决定，系统生成）
- `HOLD_EXTENDED`（附新三要素的延续）

**final_decision**

- `SUPERVISOR_REVIEWED`（主管复核：release / continue / escalate）
- `APPEAL_DECIDED`（独立复核结果）
- `AUTHORITY_RESPONDED`（原有，授权等级 L0–L3 + 文书编号）
- `FUNDS_RELEASED`（原有，放行）
- `PAYMENT_STOPPED`（止付，必须附依据）
- `DECISION_SUPERSEDED`（更新的有效决定覆盖执行动作）

### 15.3 跨业务隔离

- 案件数据默认仅供本案件视图与合规审计读取；
- 其他业务系统只能访问“外溢视图”，其中**仅有**：客户确认的风险教育完成记录，或已受案/已法律定性的状态码；不含信号原文、印象记录、陪同者信息、申诉内容；
- 放行结案后外溢视图在该客户维度立即为空；转正式流程的按法律规定处理。

### 15.4 警方响应分级与披露门

| 级别 | 情形 | 可提供 |
|---|---|---|
| L0 无记录 | 仅电话沟通 | 可告知“本行正按流程核实”，不提供客户信息 |
| L1 口头建议 | 民警电话建议关注 | 可回告联系结果等有限信息，不出账户数据 |
| L2 已受案 | 受案回执/协查请求 | 可提供与本案直接相关的有限材料（事实信号、联系记录摘要） |
| L3 正式文书 | 调取证据通知书/协助冻结文书等 | 按文书范围提供完整证据、流水与资金去向；止付冻结按文书执行 |

导出动作前强制校验授权等级与文书编号；L0/L1 的导出申请自动拒绝并记录。

## 16. 正当交易保护（防误伤清单）

1. 购房用途可形式核对（合同编号可验真、收款方与预售资金监管账户/卖方一致、中介可拨通）→ 只做单独意愿确认，不进入暂停；
2. 客户表述一致、自愿、明确知道金额与后果 → 即使家属反对也放行；
3. impression 信号零暂停权重；
4. 加速条款（§8）与申诉超时解除（§11）双重兜底；
5. 放行结案 24 小时内清理全部外溢标记；
6. 指标同时考核“被骗拦截”与“误伤”：误伤率/申诉成立率升高时收紧触发灵敏度并回溯培训，不只奖励拦截数。

## 17. 审计与指标

- 每案完整时间轴（含每次界面操作、推送、告知交付凭证），保存期限按监管规定；
- 核心指标：开案数、初始暂停率、各段超时默认放行次数（**按责任人统计**）、申诉率/成立率、平均暂停时长、转正式流程数、止付数、购房加速申请数与兑现时长、误伤投诉数、重复事件投递率、版本冲突数；
- 每周抽查：暂停三要素齐全率、信号分级合规率、告知书按时交付率、披露门拦截的违规导出尝试次数。

## 18. 异常与失败模式

| 情形 | 处理 |
|---|---|
| 主管联系不上 | 界面按上报链自动升级（后备主管→支行长），时限不变；到点无有效决定→放行 |
| 系统宕机/通知丢失 | 支付侧以指令截止时间为准，逾期指令无效；恢复后按事件时间轴重放，幂等去重 |
| 客户执意当场取款且不满足暂停要件 | 必须放行，转事后风险提示与教育记录；禁止软性拖延（不点钱、不叫号） |
| 陪同者威胁闹事 | 安保与警方按治安流程处理，与客户交易核实分开；不因此自动暂停客户资金 |
| 多渠道同名案件 | 以同一客户 + 同一交易意图归并，支付侧自然键去重；不能归并的并行案件各自独立计时 |
| 客户届满后改变主意不取款 | 记录客户放弃，正常关闭；不产生任何不利标记 |
